# CacheArena

Lavik-owned benchmark comparison site inspired by DBARENA’s data-first presentation. It makes no claim of independent testing or Supabase/DBARENA affiliation.

## Development

Requires Node.js 22 or newer.

```sh
npm ci
npm run build
npm start
```

Preview at http://127.0.0.1:4173. This is a pre-rendered static site with native browser JavaScript, hosted on Cloudflare Workers Static Assets. It has no database, tracking, external fonts, or runtime framework dependency. The overview, comparison, methodology, and 404 pages are generated by `scripts/build.mjs`; the initial comparison and all methodology content are readable without JavaScript.

## Data and fairness

- `public/data/september-results.csv`: all 146 original September points (22 new Lavik, 124 reused controls).
- `public/data/august-report.md`: 27 local summary measurements and three separate Azure observations.
- `public/data/results.json`: normalized measurements used by the UI.
- `public/data/manifest.json`: source revision, retrieval date, and SHA-256 hashes of the original source snapshots.
- `src/data.mjs`: cohort definitions, product metadata, and selection rules.

Source repository revision: `d88a5e8fdcc5702272b26f9853f4baad7a146988`. See `/methodology` for exact source links, conditions, uncertainty, and limitations. Source reports retain the EloqData copyright notice and Apache 2.0 license. The normalized dataset is a transformation of those reports; original data is not modified.

Never combine rankings across cohorts. Default September selection chooses a system’s maximum QPS and keeps latency from that same point. Redis/Valkey thread defaults are chosen by peak throughput across the complete connection sweep. Switching to latency changes ordering, not point selection. August uses fixed concurrency. Azure results appear separately without rank. QPS is rounded only for display.

To update data, pin a new source revision, preserve the source reports and original CSV, regenerate normalized records, update hashes and displayed metadata, and rerun all checks. Do not fetch mutable upstream results on page load.

## Verification

```sh
npm test
npm run build
npm run test:dom
# With the preview server running and a Playwright browser installed:
npm run test:browser
# Sandboxed macOS fallback, without a local listening port:
BROWSER_SINGLE_PROCESS=1 TEST_STATIC=1 npm run test:browser
```

Data tests verify every imported measurement against its original source, source hashes, reported peak selections, all selector combinations, cohort boundaries, latency ordering, and explicit thread settings. DOM checks verify local links, anchors, deep links, CSV download wiring, and interactions. Browser checks cover desktop/mobile layouts and screenshots. The optional WebMCP configuration tool uses the same UI state; DOM tests validate it in a simulated context, not a native WebMCP browser.

## Cloudflare deployment

`wrangler.jsonc` names the Worker `cachearena` and configures `cachearena.com` as a custom domain.

```sh
npx wrangler login
npm run deploy
```

Cloudflare creates the custom-domain DNS and certificate through its Workers integration. Keep credentials outside source control. `.wrangler-local/` is ignored and may hold temporary deployment credentials in restricted environments; it must never be published. Only `dist/` is deployed.

The deployment wrapper uses the project-local Wrangler session when present. That session was refreshed during the initial deployment because the restricted environment could not update the global login. Other checkouts can reauthenticate with `wrangler login` if their old session expires.

## Structure

- `src/render.mjs`: shared static and interactive HTML rendering.
- `src/app.mjs`: controls, query-string state, CSV export, optional WebMCP tool.
- `src/styles.css`: responsive theme and chart styling.
- `public/`: source evidence, metadata, licensed font, and security headers.
- `scripts/build.mjs`: deterministic static-page generation.
- `tests/`: provenance, interaction, and browser checks.
